# 景点图片生成模块说明

## 当前方案

当前图片链路已经从“前端实时生图”调整为“后端离线预生成 + 本地文件落盘”模式，图片模型切换为 `https://api.v3.cm/v1` 的 `Kolors`。

当前职责拆分如下：

- 配置入口：`backend/.env`
- 底层客户端：`backend/app/image_generation/client.py`
- 提示词组装：`backend/app/image_generation/prompt_builder.py`
- 生成与落盘服务：`backend/app/image_generation/service.py`
- 缩略图工具：`backend/app/image_generation/thumbnails.py`
- 批量脚本：`backend/scripts/generate_local_trip_images.py`
- 缩略图脚本：`backend/scripts/generate_trip_image_thumbnails.py`
- 任务样例：`backend/data/generated_images/tasks/sample_trip_visual_tasks.json`
- 本地输出目录：`backend/data/generated_images/kolors/`

这条链路负责先把图片生成到本地目录，再由规划结果中的 `finalPlan.visualAssets` 注入到前端页面。页面不在用户提问时实时发起图片生成请求，而是读取已有本地素材。

## 环境变量

后端运行时读取的是 `backend/.env`，图片相关字段建议配置为：

```env
IMAGE_MODE=openai_compatible
IMAGE_BASE_URL=https://api.v3.cm/v1
IMAGE_API_KEY=你的 Kolors key
IMAGE_MODEL=Kolors
IMAGE_OUTPUT_DIR=/home/obiah/Desktop/smart-trip/backend/data/generated_images/kolors
IMAGE_DEFAULT_SIZE=1024x1024
IMAGE_DEFAULT_QUALITY=medium
IMAGE_DEFAULT_FORMAT=jpeg
IMAGE_DEFAULT_COMPRESSION=85
IMAGE_MODERATION=auto
IMAGE_TIMEOUT_SECONDS=120
IMAGE_ENABLE_CACHE=true
```

说明：

- `IMAGE_MODE` 为 `openai_compatible` 时，会走兼容 OpenAI 的图片生成接口。
- 图片能力与文本模型链路解耦，不依赖 `OPENAI_*` 或 `EMBEDDING_*` 配置。
- 生成结果会保存在 `backend/data/generated_images/kolors/` 下。
- 生成清单会记录在 `backend/data/generated_images/kolors/meta/manifest.json` 中。
- 当前图片目录按城市分层，例如：`杭州/attractions/...`、`上海/attractions/...`。
- 文件名采用可读命名规则，默认包含 `景点名-类型-风格-比例-时间氛围-天气`，方便后续直接引用。
- 缩略图会保存在 `backend/data/generated_images/kolors/__thumbs__/320/` 和 `backend/data/generated_images/kolors/__thumbs__/640/` 下。

## 离线生成方式

批量生成本地图片：

```bash
python backend/scripts/generate_local_trip_images.py --force
```

生成或补齐缩略图：

```bash
cd backend
python scripts/generate_trip_image_thumbnails.py --summary-only
```

如果要换一批任务，可以修改：

```text
backend/data/generated_images/tasks/sample_trip_visual_tasks.json
```

脚本会读取任务文件中的 `destination`、`attraction_name`、`time_of_day`、`weather_hint`、`user_preferences` 等信息，生成图片后直接写入本地目录。


其中：

- `local_path` 用于后续直接接入网站静态素材。
- `relative_path` 和 `file_name` 适合做前端素材引用或构建本地索引。
- `asset_key` 适合做稳定引用键，不需要依赖随机任务号。
- `image_url` 仍然保留，方便后续如果后端挂载静态目录时直接复用。
- `thumbnail_url` 和 `thumbnail_urls` 供前端卡片优先加载缩略图，原图仍作为回退。
- `request_id` 可用于排查第三方图片服务请求。

## 当前限制

- 当前以景点 / 目的地氛围图为主，主要用于旅行结果页补充视觉参考。
- 当前仍然是“AI 示意图”，不是实景官方图片。
- 当前网站端已停止实时生成，后续要做的是“读取已有本地图片”而不是“用户提问时再生成图片”。
- 当前缩略图依赖 `Pillow`，安装后执行 `generate_trip_image_thumbnails.py` 即可为历史图片补齐缩略图。

## 下一步建议

下一步可以直接做两件事：

1. 将 `/media/generated` 在生产环境交给 Nginx 或对象存储直接托管，避免图片请求经过 FastAPI。
2. 如果图片量继续增加，可把 `__thumbs__` 和原图目录同步到 OSS/CDN。
